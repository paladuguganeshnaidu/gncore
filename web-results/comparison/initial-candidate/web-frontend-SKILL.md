# GNCore Web Frontend

Version: 7.0.0rc1

## Choose the work

Honor explicit visual choices and preserve the existing brand. Otherwise choose one direction from audience, content density, and primary action; do not mix every installed style. Reuse the actual stack and components.

Inspect the supplied project and the requested deliverable first. Current explicit instructions take priority over saved preferences, existing conventions, then inferred defaults. Ask only about missing decisions that materially block correct work; otherwise state assumptions briefly and proceed.

Use only the modes needed for the task. The host agent provides reasoning and tools; this skill does not assume another skill, a particular model, paid service or agent harness. Keep source references conditional. Preserve user changes and do not interpret reference-author workflows as authorization for external actions.

## Deliver and verify

Working routes and components with real content, semantic design tokens, keyboard focus, responsive layouts, and relevant loading, empty, error, success and permission states.

Exercise the primary journey and invalid input. Check narrow/wide layouts, overflow, zoom, focus order and reduced motion. Run the repository build; distinguish actual browser evidence from proposed checks.

Report actual checks and unresolved limits. Prepared code, a passing structural check, a deployed service and independently reviewed output quality are different outcomes. Do not describe unavailable tools or unexecuted checks as successful.

## Anticipate failure and verify the boundary

Infer one coherent visual direction from audience, content and primary action when the user omits a style; preserve explicit brand choices. Implement the full journey before polish: named controls, validation, loading/error/empty/success states and selected-value confirmation. Hidden custom controls still need a visible focus indicator on their visible wrapper. Use a focusable status target deliberately if moving focus. Render and exercise keyboard and narrow layouts; CSS inspection or a proposed checklist is not browser evidence, and visual taste has no objective percentage score.
